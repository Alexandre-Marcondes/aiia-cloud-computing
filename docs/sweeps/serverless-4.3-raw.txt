SLS Practice 1 -- Part 4.3: multi-camera sweep vs the Part 3 serverless pipeline
================================================================================
Note     : deployment identifiers are shown as <placeholders>; nothing else altered.
Target   : Functions Flex `<function-app>` + AI Vision S1 `<vision-account>` + storage `<storage-account>`
Sender   : src/local_stream.py --cameras N --interval 5 --seconds 60 --no-display
           (uploads to the `raw` container via --blob-connection-string)
Signal   : the `raw` blob count, sampled every 10 s. The function deletes each blob
           after processing, so the count is the *unprocessed backlog* -- a direct,
           real-time signal, unlike the Azure Monitor metric windows which lag and
           overlap between runs.
Load     : 1 frame / 5 s per camera (the Part 4 cadence); offered rate = N/5 fps.
Sender   : validated as NOT the bottleneck -- N=256 uploaded 3073/3072 frames (51 fps).
================================================================================

A stalled backlog is stuck in Event Grid's retry backoff (invocations fail on Vision
429 throttling), so it does not drain; the `raw` container was cleared after each run
to stop the retry storm.
